# C++ preparation and ABI review

- Fixed in `execution.cpp`: JSON object iteration is lexical by string key, while canonical `ka_abi.load_snapshot` inserts skill rows by ascending numeric ID. The adapter now validates and sorts both skill rows and effect resources by numeric ID before calling the ABI. This keeps `KaBattle.rows_sorted` on its binary-search path and aligns the whole-state checksum with canonical load order.
- Coverage gap: `admission.cpp` rejects `items`/`itemStock`, and its input validator admits only `holy_herb` or `finish`; `preparation.cpp` contains an item-input path that is unreachable through `admit -> prepare`. Finish inputs also pass admission but fail later in preparation. Both cases fail closed, so they reduce coverage rather than produce a wrong battle. Either add canonical item validation to admission and reject finish there, or document the unsupported subset consistently.
- Compared default-start preparation against `_build_engine`, `combat_setup.prepare_setup`, `special_enemy_baseline`, and `ka_abi.engine_snapshot`: formation ordering, effective parameter/equipment math, enemy level/follower draws, HP/MP refill, identity/roster order, and supported start-state snapshot fields have direct counterparts. Captured placement, household expansion, vehicle state, linked parameters, and initial invoking state remain rejected.
- No tests, parity runs, battles, benchmarks, or timings were run in this review. Compilation has not been run after the adapter edit.
