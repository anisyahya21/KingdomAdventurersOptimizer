# C++ pipeline integration notes

`pipeline.hpp` expects `kaopt::Json admit(const Json&,const Json&)`, `prepare(const Json&,const Json&)`, and `execute(const Json&,const std::string&)`. The execution result must contain `ok:true`, all 74 report fields, `earned` as a finite number or null, `nativeChecksum`, and positive integer `reportBytes`. The `run(config)` entry expects `rawCandidates`, `tables`, `kernelPath`, `outputDir`, `executors`, `generations`, `seedStart`, `seedCount`, and provenance with engine, mechanics, policy, ABI, arena, raw input, tables, and kernel SHA-256 values. Every trial applies its seed to `seedPointers` before admission/preparation; this defaults to `/mathSeed` and `/libSeed` and fails closed if either field is absent or non-integer. `scorePointer` defaults to `/earned`. `mutations` is an optional array of explicit integer JSON-pointer edits with `pointer`, inclusive `min`/`max`, and optional `step`/`stride`. Out-of-range mutations fail closed.

The output directory is locked for the run. The result store is a single-writer JSONL journal. Each batch flushes and calls `FlushFileBuffers` on Windows or `fsync` on Unix before becoming resumable. Startup checks exact provenance and search policy, rebuilds fresh numeric Earned means in sorted trial-ID order, and truncates only an unterminated tail; malformed complete rows or mismatched provenance fail closed. The search policy binds mutations, seed pointers/range, score path, and generation count. Candidate IDs use the root SHA-256 helper over complete canonical per-seed raw scenarios; strategy IDs group seeds. Each valid record retains the prepared snapshot and SHA-256 of its canonical JSON serialization. Valid native outcomes with null Earned are saved as evidence and excluded from fitness means. Admission/preparation rejections and invalid execution results go to `errors.jsonl` with raw intent, seed, prepared snapshot when available, provenance, and reason; they never enter the evidence journal. `generations` is applied independently to each encountered `encounterId`; each encounter has its own measured mean-Earned survivor pool and tie-break by strategy ID, so one encounter cannot starve another. `status.json` reports state, counts, startup time, elapsed time, and output paths.

Current limits: 100,000 initial/generated candidates, 1,000,000 seeds per invocation, and 256 executor threads. Candidate mutation is intentionally explicit; this pipeline will not guess schema semantics or clamp invalid values. Admission and preparation run once per seed-specific scenario. Pending jobs/results are processed in batches capped at twice the worker count. Root must bind the callbacks to the actual native kernel. Compilation of this translation unit does not establish end-to-end behavioral parity.
